# Prescription label capture and OCR

Version 0.15.5 replaces repeated live OCR with guided capture. The camera opens but does not run recognition until the person taps **Capture label panel**. On browsers with `ImageCapture`, it requests a full-resolution still; otherwise it compares three nearby frames and chooses the sharpest before running a quick on-device OCR pass. The text appears for correction, then the person captures the next label face (medicine, directions, pharmacy). A slower multi-pass read and barcode read are optional for the selected panel. Fields are auto-suggested only when the selected reading reaches the confidence threshold; lower-confidence text remains visible to correct. Photos and OCR text stay in the browser; only an explicitly chosen NDC lookup sends the code to the public drug directory. The person scanning must verify every field against the bottle before saving.

## Curved bottles

Open Live-scan prescription bottle from Add prescription, Edit prescription, or Scan prescription label from the cabinet. The rear camera opens first where browser permissions allow it. Center the medicine name and strength in the guide, hold still, and tap **Capture label panel**. Turn to the directions, then pharmacy details, and tap **Capture next label panel** after each turn. OCR never runs repeatedly in the background. Up to eight distinct panels can be captured; start over before scanning another bottle. A single face cannot reveal hidden text on the back or reconstruct characters lost to blur or glare. If camera access is unavailable, use the photo choices instead.

Each quick capture uses one enhanced-contrast image and a single OCR layout after still capture. If the result needs help, **Try a slower detailed read** runs magnified, alternate-layout, thresholded, and optional cylindrical correction passes on the current panel. Crop controls and photo rotation remain available, followed by **Read adjusted label**. Original pixels are kept in memory up to 3600 pixels on the longest side; OCR crops have a white border and are rescaled within bounded dimensions. Barcode decoding is separate and runs only after **Read barcode on this panel** is tapped.

Readable lines are filtered by per-line OCR confidence, and useful lower-confidence text is shown so the person can correct rather than receive an empty result. Duplicate panels are not added again. Detailed rereads replace the current panel instead of duplicating its text. Separate views contribute missing structured fields; conflicts are shown for review. Existing form values, including corrections, are not overwritten by another panel. Medication names, numbers, strength and directions are not guessed or spelling-corrected against a drug list. Review the actual label and confirm before handing the draft to the cabinet form; saving there remains separate.

Live camera uses HTTPS/browser permission, prefers the rear camera and requests continuous autofocus when supported. It captures a still only after a tap; no frames are recorded or uploaded. The OCR worker remains warm between panels. Camera tracks stop on Stop camera, cancellation, account changes and dialog close. Photos, crops, recognized text and candidates are cleared on start over/close/account changes. No new dependency or server storage is added.

## Validation limits

Desktop synthetic-label OCR, angled front/side views, field preservation, conflicts and cancellation can be tested automatically/in a browser. They do not prove focus performance on a particular phone or accuracy on a real curved prescription bottle. A real phone test remains necessary; do not describe this as guaranteed recognition of every field. If information is not printed or legible, it remains blank for review.

Recognition guidance: https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html and https://github.com/naptha/tesseract.js/blob/master/docs/api.md .
